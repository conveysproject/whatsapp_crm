# WBMSG Own Auth (replace Clerk) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace Clerk with WBMSG's own authentication (email+password, email code, WhatsApp code, Google, Facebook) across API, web and mobile, then remove Clerk completely.

**Architecture:** An auth module inside the Fastify API (`apps/api/src/auth/`) is the single identity authority. It issues Ed25519-signed 10-minute access JWTs and rotating, hashed refresh tokens. `AUTH_PROVIDER=clerk|wbmsg` selects which identity verifier the existing `plugins/auth.ts` uses, and `resolveAuthContext` (roles, permissions, org scoping) stays unchanged. Web uses a Next.js backend-for-frontend with an httpOnly refresh cookie and a drop-in `useAuth()`; mobile uses SecureStore.

**Tech Stack:** Fastify 4, Prisma/Postgres (hand-written SQL migrations), Redis (ioredis), `@node-rs/argon2`, `bcryptjs` (legacy verify only), `jose`, `arctic` (OAuth, Phase 4), Vitest; Next.js 15; Expo 57.

**Spec:** `docs/prd-own-auth.md` (read it first; section numbers below refer to it).

**Plan shape:** this file has the **roadmap for all phases** and **full TDD tasks for Phases 0–1** (API core, shipped dark). Phases 2–6 each get their own detailed plan file **when the previous phase merges**, written against the real Phase 1 interfaces listed here. Each phase leaves the product working (Clerk stays live until Phase 5).

## Global Constraints

- End state: zero Clerk (`git grep -i clerk` finds only historical docs; no `@clerk/*`, `svix`, `CLERK_*`). Clerk is touched only for the one-time user export.
- `User.id` of existing users never changes; migrated `auth_accounts.id` = Clerk user ID. New IDs: `usr_` + 26-char random (base32 lowercase, CSPRNG).
- Roles, permissions, `resolveAuthContext`, org scoping, demo tokens: **no behavior change**.
- Passwords: argon2id `memoryCost=65536` (KiB), `timeCost=3`, `parallelism=1`; length 8–128; no composition rules. Legacy `bcrypt` verified then rehashed to argon2id on success.
- Access JWT: EdDSA/Ed25519, TTL **600 s**, claims `iss="wbmsg"`, `aud="wbmsg-api"`, `sub`, `sid`, `typ` (`user`|`admin`), header `kid`.
- Refresh token: 32 random bytes base64url, stored as SHA-256 hex, rotated on every use, family revoked on reuse. Lifetime 30 days sliding (`user`), 12 h absolute (`admin`).
- One-time codes: 6 digits from CSPRNG, stored as HMAC-SHA256(`AUTH_CODE_PEPPER`, `purpose:target:code`), expiry 600 s, max 5 attempts, single use.
- Rate limits (Redis): password attempts 5 / 15 min per account; code sends 3 / 10 min per target; any auth endpoint 20 / 10 min per IP.
- No user enumeration: identical status, body and (padded) timing for unknown-account vs wrong-secret; request endpoints always answer `202 {"ok":true}`.
- Emails go through `sendMail` (`apps/api/src/lib/mail.ts`); never log codes, tokens, hashes or env secrets.
- Migrations are hand-written SQL in `apps/api/prisma/migrations/<timestamp>_<name>/migration.sql` (local DB is drifted; never `prisma migrate dev`). Additive only until Phase 6.
- Customer-facing copy: never mention competitors; plain language.
- Known flaky API tests: `segments.test.ts`, `conversations.test.ts`. Any other failure is real.

## Review Focus

1. **Email case and whitespace:** `Foo@X.com ` and `foo@x.com` are the same account at signup, sign-in, reset and import. Tested in Task 2 (`normalizeEmail`) and Task 8.
2. **Concurrent refresh** (two browser tabs refresh with the same token within ~1 s): must not log the user out. 10-second grace returns the already-rotated pair for the same token. Tested in Task 5.
3. **Deactivated user with a live session:** must be rejected within 60 s (user `isActive=false` is already checked by `resolveAuthContext`; sessions also revoked). Tested in Task 7.
4. **Code reuse and cross-purpose reuse:** a `password_reset` code can't be used as `signin_email`, and any code works only once. Tested in Task 6.
5. **Legacy bcrypt hash longer than 72 bytes of password:** bcrypt truncates. Verify against the bcrypt rules; rehash to argon2id on success. Tested in Task 3.
