# One Phone Number Implementation Plan (short spec + plan)

**Goal:** Stop asking users for phone numbers we don't use, and bill in INR/USD from a number we can trust.

**Owner decision (2026-10-19, "Decide which will best"):**
1. Remove the optional "Mobile number" field from the invitation-accept page (never verified, only shown in Members).
2. Billing currency = owner's explicit choice (Admin → Billing) → country of the organization's connected WhatsApp number (vendor setting `current_phone_number_number`, verified by Meta; +91 = INR, any other = USD) → location mentioning India → USD. The Account Details "Phone" no longer affects billing.
3. Keep Account Details "Phone" as a plain contact field (no schema change).

**Non-goals:** no migration; existing `users.mobile_number` values stay and still show in Members; the API keeps accepting `mobileNumber` (old clients) but no web screen sends it.

## Tasks

### Task 1: Billing currency from the WhatsApp number
- `apps/api/src/lib/billing/payment-links.ts`: `OrgCurrencyHints` = `{ settings, location, wabaPhone }`; `currencyForOrg` order as above; export `ORG_CURRENCY_SELECT` (org `settings`, `location`, and `vendorSettings` filtered to `current_phone_number_number`) and `orgCurrencyHints(org)`.
- Callers: `lib/billing/statement-payment.ts` (`ensurePaymentLinks`) and `routes/admin-billing-statements.ts` (list) use the shared select + hints.
- Tests: `payment-links.test.ts` (WhatsApp number beats location; non-Indian WhatsApp number → USD even if location says India; Account Details phone ignored), `statement-payment.test.ts`, `admin-billing-statements.test.ts`.

### Task 2: Invitation page without the mobile field
- `apps/web/app/invitations/[token]/accept/page.tsx`: remove the field and `mobileNumber` from both request bodies.

### Verify

## Security
No route, RBAC or tenant scoping changes; the WhatsApp number is read per organization by id (same org as the statement).
