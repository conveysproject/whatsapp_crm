## Track 3 — WhatsApp Chatbot Development Service Page

### Scope
Add one new entry to `SERVICE_NAV` and one full `ServiceData` object to the `SERVICES` array in `lib/services-data.ts`. The existing `[slug]` dynamic route handles rendering — no new page file required.

### SERVICE_NAV entry
```ts
{ slug: "whatsapp-chatbot-development", title: "WhatsApp Chatbot Development", column: "Digital & IT Solutions" }
```
Insert after the `whatsapp-crm` entry.

### ServiceData

- **slug:** `whatsapp-chatbot-development`
- **column:** `"Digital & IT Solutions"`
- **title:** "WhatsApp Chatbot Development"
- **tagline:** "Automate Customer Conversations on WhatsApp — 24/7"
- **metaTitle:** `"WhatsApp Chatbot Development Services | AI & Rule-Based Bots | Conveys"`
- **metaDescription:** `"Build WhatsApp chatbots that qualify leads, answer FAQs, and handle orders 24/7. Rule-based and AI-powered. Meta-approved API only. Fixed pricing."`

**Offerings (6):**
1. Rule-Based Chatbot — keyword/button-triggered flows for FAQs, menu navigation, and structured data collection
2. AI-Powered Chatbot — Claude/GPT integration for natural language conversations and intent detection
3. Lead Qualification Bot — automated prospect qualification, scoring, and CRM handoff
4. E-commerce & Order Bot — catalogue browsing, order status, returns, and payment links via WhatsApp
5. Customer Support Automation — ticket creation, status updates, escalation to human agent
6. Analytics Dashboard — conversation volume, deflection rate, handoff rate, and CSAT tracking

**Process (6 steps):**
1. Discovery & Use Case Mapping (Day 1–2) — map target users, conversation flows, and integration points
2. Conversation Flow Design (Day 3–5) — build flow diagrams for every path including fallbacks and handoffs
3. Development & API Integration (Week 2–3) — build bot on Meta WhatsApp Cloud API, connect to CRM/DB
4. Testing & QA (Week 3) — test every flow, edge case, and failure scenario on real WhatsApp numbers
5. Go-Live & Monitoring (Week 3–4) — production launch, delivery monitoring, fallback alerts configured
6. Optimisation & Support (Ongoing) — monthly review of conversation logs, flow improvements, new intents added

**Tech stack (8):**
- Meta WhatsApp Cloud API (Messaging)
- Node.js / Fastify (Backend)
- Claude API / OpenAI GPT-4o (AI)
- PostgreSQL (Database)
- Redis / BullMQ (Queue)
- React (Admin Dashboard)
- AWS / Railway (Hosting)
- Sentry (Error Monitoring)

**FAQs (5):**
1. Do I need the WhatsApp Business API to use a chatbot? — Yes. The chatbot connects to your WhatsApp number via the Meta Cloud API. We handle the full WABA setup if you don't have it yet.
2. Can the chatbot hand off to a human agent? — Yes. We build escalation triggers — if the bot cannot answer or the user requests a human, the conversation is routed to your support team in real time.
3. How long does it take to build a WhatsApp chatbot? — A rule-based chatbot with 5–10 flows takes 2–3 weeks. An AI-powered bot with CRM integration takes 4–6 weeks. We give you a precise timeline after the discovery call.
4. Can the chatbot handle multiple languages? — Yes. We build multilingual bots that detect the user's language and respond accordingly — typically English + one regional language (Hindi, Arabic, etc.) as a starting point.
5. What happens when the chatbot fails to understand a message? — We design fallback flows: the bot acknowledges it didn't understand, offers a menu of options, and escalates to a human agent after two failed attempts. No conversation dead-ends.
